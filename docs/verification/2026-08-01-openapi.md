# OpenAPI verification

## Scope

AnimeGoNet uses the official .NET 10 OpenAPI generator to expose the complete Minimal API
contract at `/openapi/v1.json`. The document has deterministic operation IDs and tags,
describes modern and legacy access-key alternatives, excludes itself, and retains every
operation in the upstream OpenAPI baseline.

## Deterministic tests

`OpenApiDocumentTests` verifies:

- exact path/method equality with every non-excluded HTTP endpoint;
- unique stable operation IDs and exactly one known tag per operation;
- all 12 upstream compatibility operations;
- request body, response, typed path-parameter, and security metadata;
- real middleware behavior with and without the modern header;
- byte-identical documents from processes with different ports, roots, and access keys;
- absence of access keys, temporary paths, listening hosts, and ports.

The targeted Release suite passed 4/4 with no skips. A dependency vulnerability audit,
including transitives, reported no vulnerable package in any solution project. The
initial transitive `Microsoft.OpenApi 2.0.0` resolution was rejected by warnings-as-errors;
the repository pins the patched `2.7.5` release rather than suppressing the advisory.

The complete Release suite passed 1274/1274 with no skips: PluginTool 23, Plugin SDK 16,
Plugin Abstractions 12, Core 324, Data 173, and App 726. Release solution build passed
with zero warnings and zero errors.

## NativeAOT

`eng/smoke-native.ps1` requests and parses the generated document from the published
native process. It requires the expected title plus modern and compatibility paths and
rejects the isolated credential, temporary root, or runtime base URL. The same smoke is
part of the native five-RID workflow.

Local `win-x64` NativeAOT publish completed without trim or AOT warnings. The exact
published executable passed both isolated first-start and legacy YAML upgrade smokes,
including the generated OpenAPI checks, and both processes released cleanly.
