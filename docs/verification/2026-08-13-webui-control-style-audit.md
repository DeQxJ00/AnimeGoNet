# WebUI 基础控件样式审计（2026-08-13）

## 浏览器审计发现

- 作品库搜索、排序和任务筛选控件从小号 `label` 继承字体，约 11.5px；相邻按钮为 16px。
- 下载筛选操作区被 Grid 交叉轴拉伸，“应用筛选”和“重置”达到约 99px 高。
- qBittorrent 实例卡片动态创建的配置、连接测试和路径探测按钮没有样式类，使用浏览器默认灰色外观。
- Bangumi 缓存命名空间选择器、部分插件/Legacy 编辑器和离线文件输入缺少统一基础样式。
- 多个页面分别维护近似但不同的背景、圆角、padding 和字体规则。

## 统一边界

- 基础 token 固定常规控件高度 44px、圆角 10px、字体 14px，并统一边框、背景、文字和 placeholder。
- 普通未分类按钮默认采用次要操作外观；主操作、危险操作、重试、元数据时间线、导航、作品卡片和图标按钮保留各自语义样式。
- 文件输入统一容器和文件选择按钮；checkbox/radio 不套用文本控件外观。
- Prompt/JSON 等代码编辑区继续保留等宽字体和专用尺寸。
- 下载与元数据筛选操作按钮固定为 44px，不再随 Grid 行高拉伸。

## 验收

- TypeScript 构建确保动态下载器按钮带 `secondary-button`。
- 静态资源契约锁定控件 token、文件选择器和筛选按钮规则。
- WebUI DOM/可访问性测试继续验证 44px 常规控件、焦点、移动端与 reduced-motion 契约。
- NativeAOT 页面需在桌面和移动视口复核作品库、任务中心、下载工具配置、缓存与 AI 测试工具。

## 实际结果

`win-x64` NativeAOT 发布后在本地 WebUI 逐个切换全部 9 个一级菜单并检查可见
`input/select/textarea/button` 的计算样式。排除 checkbox/radio、导航、作品卡片和
Prompt 代码编辑区等明确专用控件后，没有剩余默认浏览器按钮、0px 圆角、缺失边框、
异常大于 64px 的按钮或非 14px 常规表单控件。

重点复测结果：作品库搜索/排序/方向/页大小与搜索/清除按钮均为 14px、44px、
10px 圆角；任务筛选操作从约 99px 恢复为 44px；下载器动态按钮均带
`secondary-button`；缓存命名空间选择器已使用统一背景、边框和 padding。桌面端实际
截图无横向溢出；390px 移动端响应式边界由现有 DOM/CSS 自动测试继续锁定。
